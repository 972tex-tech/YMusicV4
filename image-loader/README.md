# `:image-loader`

Module detail for the one-line summary in the root [`AGENTS.md`](../AGENTS.md) — read this before working inside the module.

our own simple Compose image loader (jvm + android + compose-iOS targets): `ImageLoader(fetchers, scaledCache?, …)` — **everything is a fetcher** (`ImageFetcher.fetch(url, cacheKey, size): DecodedImage?`, first non-null wins): `networkFetcher(client, fs, cacheDir)` = the Coil/Glide model on kmpHttp's `DiskLruCache` (body streams to disk under a byte cap, decode **from the file**, cacheKey-keyed so all sizes share one download; the client carries NO http cache), `fileFetcher()` = `file://`, custom schemes (ffmpeg album art, content providers) plug in with the public `decodeScaled`/`decodeScaledFile` helpers; decodes **scaled to the view size** (Android subsampled `BitmapFactory`, Skia draw-down on desktop/iOS via a shared `skikoMain` source set — the full-size image never stays resident), memory-LRUs decoded bitmaps, and optionally persists the scaled PNG (`ScaledImageCache` / `DiskScaledImageCache` on okio) so warm starts skip fetch + full decode. Concurrency is a **LIFO gate** (newest request first, cancellation frees the slot/stack — scroll-away cancels via composition, scroll-in preempts). `AsyncImage(loader, url, …, placeholder?, error?)` measures itself, loads at its own pixel size (64px-bucketed cache keys), shows `placeholder` while loading and `error` (→ placeholder fallback) on failure, and draws a memory-cached image on its FIRST frame via a synchronous `peek` (no placeholder flash on scroll-back) (logged breadcrumb, never thrown into composition); a resize reloads only on ≥100px growth after a 400ms settle — never per drag frame.
