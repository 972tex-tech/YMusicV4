# `:mse`

Module detail for the one-line summary in the root [`AGENTS.md`](../AGENTS.md) — read this before working inside the module.

C Media Source host for the JS YouTube player. **Not** a Kotlin `MsePlayer` / MediaCodec path.

- **JS YouTube path** — leftover + ffmpeg demux + clock live in C (`mse_ffmpeg.c` / `mse_host.c`). QuickJS `__mse*` trampolines call that C directly. **JNI has one media call: `setVideoSurface`.** Seek is JS (`seekTo` → `HTMLMediaElement.currentTime` → `__mseSetCurrentTime`), not a host export. C→JS events: `MseJsEventBridge.fire` (any thread) → `DynamicEngine.fire` → `"event"` pipe → `ymix.onEvent`. Critical C lines (starve, park/recover, ffmpeg errors) hop `mse_set_log_callback` → `MseLogBridge.fire` → `Logger.fork("mse")` (file + Sentry). Chatty `vlog`/`mse_logf` emit DEBUG; `-Pproduction=true` compiles them to `((void)0)` so format args are not evaluated. `mse_critf` INFO/WARN/ERROR always emit.
- **JVM desktop** — that C host; Compose preview blits bitmaps (JAWT on SwingPanel SIGSEGVs). Host JDK headers plus `ffmpeg-build/out/<desktop-slug>` shared libav (`FFMPEG_ROOT`) to build `libmseffmpegjni`. Same DSOs the packed `ffmpeg` CLI loads. Local files use a **separate** in-process host (`file_av.c` / `FileAvNative`), not leftover. **Linux**: audio is `aq_pulse.c` (AudioQueue subset on dlopen'd libpulse-simple); GPU decode is `mse_hwdev.c` — one process-wide CUDA (NVDEC), else Vulkan-video device for H.264/HEVC/VP9/AV1 in both hosts, frames downloaded to NV12 for the swscale blit; a codec the GPU rejects (AV1 on Pascal) falls back to software for the process. `YMUSIC_HWDEC=none|cuda|vulkan` overrides.
- **Android** — same C host; app passes a `Surface` (TextureView) into C. NDK build needs `FFMPEG_ROOT` (shared libav per ABI). Audio: the C decode loop fills a PCM ring that `MseAudioOutput` (a Looper thread per host) drains into Media3's `DefaultAudioSink` through `mse_host_dac_poll`/`_report`; the sink's playout position drives the A/V clock, and its AudioTrack is small (100–200 ms) because the host decodes only `0.35 s + track buffer` past the clock and a streaming track starts only once full. Video is `AMediaCodec` into that Surface (HW if the SoC has it, Google software codec otherwise). libav + CPU blit is only if MediaCodec configure/start fails. Software volume/EQ/bass/virtualizer live in `audio_fx.c` on the PCM fill path; ExoPlayer local files JNI the same DSP via `AudioFxNative`. The sink's audio session id is `MseVideoSurface.audioSessionId()`, for system audio-effect apps.
- **Apple** — the same C in this module (`libmsehost.a` + cinterop) when `ffmpeg-build/out/ios-*` exists. `bindNativeMse` is `MseHostNative.create()` + `vtable()` into QuickJS, like JVM/Android.
